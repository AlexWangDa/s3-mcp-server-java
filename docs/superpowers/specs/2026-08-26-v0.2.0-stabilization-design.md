# S3 MCP Server v0.2.0 Stabilization Design

## Purpose

Version 0.2.0 turns the repository from a demonstration into a safe, reproducible STDIO MCP server. A fresh checkout must build without a preinstalled Maven, start with documented configuration, expose the existing eight S3 tools, and provide automated evidence that the tools work against an S3-compatible service.

## Selected Approach

The release will use staged stabilization. Tests and component boundaries come first, AWS SDK v2 migration follows in a separate change, and Spring AI/Spring Boot upgrades happen last. This is preferred over a single dependency-upgrade rewrite because failures remain attributable to one change, and over a documentation-only patch because the current configuration and test design are not reliable enough for users.

## Scope

The release includes:

- a complete, executable Maven Wrapper pinned to Maven 3.9.11 with distribution checksum verification;
- validated Spring configuration for S3 connectivity and tool policies;
- AWS default credentials, explicit credentials, custom endpoints, regions, HTTPS, and path-style access;
- local-path containment, optional bucket and key-prefix restrictions, and a default remote read-only mode;
- unit, MinIO integration, and STDIO protocol tests;
- AWS SDK for Java v2 and stable Spring AI/Spring Boot dependencies;
- CI, release-ready documentation, and working MCP client examples.

The release does not add delete, copy, move, batch, multipart, Streamable HTTP, native-image, or container distribution features. Those belong to later releases.

## Component Design

### Configuration

`S3Properties` will bind properties under `s3` and use Jakarta Bean Validation. It replaces manual argument parsing and application-wide static fields.

Supported properties are:

| Property | Default | Meaning |
| --- | --- | --- |
| `s3.endpoint` | unset | Optional S3-compatible endpoint override, including `https://` or `http://`. |
| `s3.region` | provider chain | Signing region; required when an endpoint override is set. |
| `s3.access-key` / `s3.secret-key` | unset | Optional explicit credential pair; both must be present together. |
| `s3.session-token` | unset | Optional session token, valid only with the explicit credential pair. |
| `s3.path-style-access` | `false` | Enable path-style addressing for providers such as local MinIO. |
| `s3.presign-duration` | `PT15M` | Presigned GET URL lifetime, limited to 1 minute through 7 days. |
| `s3.local-root` | current working directory | Root for all upload sources and download destinations. |
| `s3.read-only` | `true` | Reject remote mutations (`uploadObject` and `createDirectory`). |
| `s3.allowed-buckets` | empty | Optional allowlist; empty means all buckets visible to the credentials. |
| `s3.allowed-prefixes` | empty | Optional key-prefix allowlist applied to every allowed bucket. |
| `s3.allow-local-overwrite` | `false` | Permit downloads to replace an existing local file. |

Spring's relaxed binding makes these available as environment variables such as `S3_ENDPOINT` and `S3_LOCAL_ROOT`. If explicit credentials are absent, the AWS SDK v2 default credentials provider chain is used, including `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, profiles, container credentials, and instance roles. Secrets must never be logged.

### Client Construction

`S3ClientConfiguration` creates injectable singleton `S3Client` and `S3Presigner` beans. It applies the configured region, endpoint override, credentials provider, and path-style setting consistently. HTTPS is the normal default; HTTP is accepted only when the endpoint explicitly uses `http://`, which supports local MinIO without silently weakening production traffic.

The application class becomes a standard Spring Boot entry point and only registers the MCP tool callback provider. Startup validation failures identify the property and remediation without printing secret values.

### Local File Policy

`LocalPathPolicy` is the only component allowed to turn tool strings into `Path` objects. Relative paths resolve below `s3.local-root`; absolute paths are accepted only when they remain inside that root. Upload sources must be existing regular files. Download parents must exist, and downloads reject an existing destination unless `s3.allow-local-overwrite=true`.

Containment is checked using normalized absolute paths and real paths for the root, existing source, and destination parent. Symlinks that escape the configured root are rejected. Downloads write to a temporary sibling file and move it into place only after the S3 transfer succeeds.

### S3 Access Policy

`S3AccessPolicy` validates bucket and object-key access before every SDK call. When allowlists are configured, bucket names must match exactly and keys must start with one allowed prefix. Bucket listings are filtered rather than exposing disallowed names. Remote-mutating tools fail before contacting S3 while `s3.read-only=true`.

IAM or provider credentials remain the primary authorization boundary; application allowlists add defense in depth and do not replace least-privilege credentials.

### MCP Tools

`S3Service` receives `S3Client`, `S3Presigner`, `S3Properties`, `LocalPathPolicy`, and `S3AccessPolicy` through constructor injection. The existing tool names remain stable:

- `getBucketList`
- `getBucketInfo`
- `listObjects`
- `getObjectMetadata`
- `generatePresignedUrl`
- `downloadObject`
- `uploadObject`
- `createDirectory`

Public tool results use repository-owned records rather than AWS SDK model objects. Mutations and downloads return an operation result containing success, bucket, key, and a safe message. Tool descriptions state whether an operation reads local files, writes local files, or mutates S3. Pagination behavior remains compatible in v0.2.0; a ListObjectsV2 API change is deferred.

## Errors and Logging

Validation and policy failures use a dedicated `S3ToolException` with stable codes such as `INVALID_CONFIGURATION`, `ACCESS_DENIED`, `PATH_OUTSIDE_ROOT`, `READ_ONLY`, `NOT_FOUND`, and `S3_ERROR`. User-facing messages include the affected bucket or key when safe, but never credentials, session tokens, presigned query strings, or unrestricted local paths.

AWS exceptions are translated at the service boundary. Tool failures are reported as MCP tool errors instead of terminating the process. STDIO stdout contains protocol messages only. `logback-spring.xml` routes diagnostics to stderr by default; users may redirect logs to a file with Spring Boot's `logging.file.name` property.

## Testing Strategy

JUnit 5, AssertJ, and Mockito cover configuration validation, credentials selection, policy decisions, path traversal, symlink escape, read-only behavior, overwrite behavior, error translation, and tool result mapping.

MinIO runs through Testcontainers for integration tests covering bucket listing, object listing, metadata, upload, download, directory markers, and presigned GET URLs. Tests create unique buckets and temporary local roots and clean their own remote objects.

A separate STDIO test starts the packaged JAR as a child process, initializes an MCP client, asserts the eight tool names, invokes a read-only tool against MinIO, verifies stdout protocol integrity, and terminates the process cleanly. The obsolete weather client is removed.

GitHub Actions runs `./mvnw -B verify` on Linux with Java 17 and 21. The integration suite must run in CI without external cloud credentials.

## Dependency Migration

Changes are sequenced as follows:

1. Restore the Maven Wrapper and add a compile-level CI baseline.
2. Introduce configuration, injected clients, policies, and tests while behavior is still attributable to the current stack.
3. Replace AWS SDK v1 with the AWS SDK v2 BOM and `s3` module. The transfer manager is excluded because multipart transfer is outside v0.2.0 scope.
4. Upgrade to Spring AI 2.0.0 and Spring Boot 4.1.1, following the official MCP upgrade notes.
5. Remove milestone and snapshot repositories once all dependencies resolve from Maven Central.

Each stage is an independently reviewable commit and must leave `./mvnw verify` passing.

## Documentation and Release Readiness

README quick-start instructions use the wrapper and obvious credential placeholders. They explain default read-only behavior, local-root containment, AWS default credentials, MinIO configuration, writable-mode opt-in, and the location of the packaged JAR. Copyable STDIO configuration examples are provided for Claude Desktop and Cursor without embedding credentials in JSON.

The repository also gains contributor instructions, a sample environment file containing placeholders only, and CI status. Version values in the POM, MCP server metadata, and documentation are kept consistent at `0.2.0-SNAPSHOT` until release.

## Acceptance Criteria

- A fresh Linux or macOS checkout runs `./mvnw verify` without a system Maven.
- Windows users can run `mvnw.cmd verify`.
- Missing or inconsistent configuration fails at startup with an actionable, non-secret message.
- Default credentials and explicit credentials both work.
- All local file access is contained under the configured root, including through symlinks.
- Remote mutations are denied by default and enabled only through explicit configuration.
- Unit, MinIO integration, and STDIO protocol tests pass in CI on Java 17 and 21.
- No test or example refers to weather tools or unrelated sample paths.
- README examples can be copied after replacing placeholders and successfully connect to AWS S3 or MinIO.
